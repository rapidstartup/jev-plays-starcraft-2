# JevBench result schema

The canonical public record is defined in
[`jevbench.schema.json`](jevbench.schema.json). It is a publication record, not
a replacement for the harness artifacts under `runs/`.

## Required identity and outcome

Every record has a `schema_version` of `"1.0"`, a stable `bench_id`, a unique
`run_id`, a canonical `status`, and a `source`.

`status` is deliberately smaller than the raw harness vocabulary:

| Public status | Raw run evidence |
| --- | --- |
| `win` | Verified task success, such as objective evidence plus a surviving Raynor |
| `loss` | Verified task failure |
| `incomplete` | The run stopped without enough evidence to call it a win or loss |
| `blocked` | The run could not start or continue because of a recorded blocker |

An SC2 API `Victory` is not automatically a public `win`. The existing harness
can record synthetic campaign results, so the packet must carry the independent
objective/UI evidence in `hq_win_evidence` and `notes` when that evidence exists.

## Field mapping from this repository

The harness writes private/raw inputs in `control.json`, `result.json`,
`events.jsonl`, and the report generated by `scripts/report.py`. A publisher
should construct one canonical record from those artifacts:

| JevBench field | Existing source | Rule |
| --- | --- | --- |
| `run_id` | run directory name or `control.json.stamp` | Keep stable for the attempt |
| `status` | `result.json.status` and verified evidence | Normalize `victory`/`defeat` only after evidence review |
| `map` | `control.json.map`, `result.json.map_name` | Use the human-readable map/environment label |
| `jev_via`, `jev_model`, `guide_model`, `memory_mode` | `control.json` | Copy labels only; never copy credentials |
| `calls`, `cost_usd` | `result.json` or report output | Use measured values; leave null when unavailable |
| `wall_seconds`, `latency_ms`, `metrics` | event/report aggregates | Include only measured values and label the unit in the field name or documentation |
| `artifact_paths` | run artifacts | Publish relative paths/labels, never machine-specific absolute paths |
| `source` and `source_url` | publisher decision | `ours` requires an independent run; `official` requires a citation |
| `blocker`, `notes` | result/evidence review | Preserve uncertainty instead of inventing a score |

`openjev_base_url` is limited to a host and optional port for backend
identification. It must never contain a key, authorization header, URL path, or
query string. Do not publish `openrouter_key_present`, `jev_api_key_present`, or
any raw event payload.

## Track values

When a record is associated with the public plan, `track` is one of the three
locked values: `test_runs`, `copycats_site`, or `launch_posts`. The schema keeps
track optional so older result packets and future task-specific records remain
readable; publishers should set it for new site rows.

The shape is intentionally game-neutral. SC2 fields such as `map` and
`hq_win_evidence` are optional, while `task`, `environment`, and scalar `metrics`
allow later non-game benchmarks without inventing game-shaped placeholders.

## Minimal examples

An independently measured SC2 attempt can be represented as:

```json
{
  "schema_version": "1.0",
  "bench_id": "LD-DG",
  "run_id": "20260921T073335Z",
  "track": "test_runs",
  "task": "Destroy the Logistics Headquarters; Raynor survives",
  "map": "traynor01 / Liberation Day",
  "status": "win",
  "jev_via": "openjev",
  "jev_model": "openjev-latest",
  "openjev_base_url": "192.168.0.10:8011",
  "guide_model": "google/gemini-2.5-flash",
  "memory_mode": "none",
  "calls": 0,
  "wall_seconds": null,
  "hq_win_evidence": true,
  "source": "ours",
  "artifact_paths": ["runs/20260921T073335Z/events.jsonl"],
  "blocker": null,
  "notes": "Single-flight enforced."
}
```

The example is a shape illustration, not a claim that this run occurred in the
current checkout. Official or blocked records use `source_url` or `blocker` as
required by the JSON Schema.
